# 游戏开发教程（ESPboy_esp8266）

本教程面向希望在本项目中开发新游戏的贡献者，目标是快速搭建“可编译、可运行、可迭代”的最小工程。

## 1. 先决条件

请先完成：

- 硬件与接线确认：`doc/相关信息.md`
- 上传链路打通：`doc/上传指南.md`

## 2. 从模板开始

推荐从模板复制：

- `starter/basic_game/basic_game.ino`
- `starter/templates/game_readme_template.md`
- `games/GAME_MANIFEST_TEMPLATE.json`

建议新建目录：

```text
games/<your_game>/
  <your_game>.ino
  README.md
  manifest.json
```

## 3. 最小开发流程

### 步骤 1：先跑通空项目

- 保留 `setup()` / `loop()` 最小框架
- 确保 `arduboy.begin()` 与 `nextFrame()` 正常运行

### 步骤 2：输入处理

- 使用 `arduboy.pollButtons()`
- 优先用 `pressed()` / `justPressed()` 做交互逻辑

### 步骤 3：渲染循环

- 每帧执行：`clear -> draw -> display`
- 先画文本调试信息，再逐步替换为游戏画面

### 步骤 4：状态机拆分

建议至少拆成：

- `MENU`（主菜单）
- `PLAYING`（游戏中）
- `PAUSE`（暂停）
- `GAME_OVER`（结算）

### 步骤 5：持久化（可选）

如果需要高分/存档：

```cpp
#include <EEPROM.h>

void setup() {
  EEPROM.begin(1024);
}

// 写入后
EEPROM.commit();
```

## 4. 性能建议

- 避免在主循环中频繁分配大对象。
- 大数组/常量优先放 `PROGMEM`。
- 字符串常量优先 `F("...")`。
- 降低不必要的全屏重绘频率。

## 5. 常见开发坑

- 上传/启动时误触发 `GPIO0(D3)`。
- 忘记 `EEPROM.begin()` 或忘记 `EEPROM.commit()`。
- 直接移植 AVR 寄存器代码导致编译失败。
- 音频逻辑未做 ESP8266 兼容处理。

## 6. 提交规范

每个新游戏建议至少包含：

1. `README.md`（玩法、按键、已知问题）
2. `manifest.json`（板卡、入口、状态）
3. 最小可运行版本（能进入并完成基本交互）

## 7. 后续进阶方向

- 加入关卡数据文件与关卡编辑流程
- 补充自动化资源转换脚本
- 引入 Wi-Fi 联网实验模块（排行榜/更新）
