# 游戏移植指南（Arduboy -> ESPboy_esp8266）

本指南用于把 Arduboy 游戏移植到本项目的 ESP8266 环境。

## 1. 适配前提

请先确认：

- 开发板可正常上传（见 `doc/上传指南.md`）
- 引脚与接线一致（见 `doc/相关信息.md`）
- 本仓库内适配库可正常编译

## 2. 目标目录规范

新游戏建议使用以下结构：

```text
games/
  <game_name>/
    <game_name>.ino
    README.md
    manifest.json
    src / *.cpp / *.h
```

推荐先从 `starter/basic_game/` 复制最小模板，再逐步替换逻辑。

## 3. 标准移植流程

### 步骤 1：导入源码

将上游游戏源码放入 `games/<game_name>/`，确保 `.ino` 文件名与目录主入口一致。

### 步骤 2：基础 API 替换

常见替换：

- `#include <Arduboy.h>` -> `#include <Arduboy2.h>`
- `Arduboy` -> `Arduboy2`
- `arduboy.getInput()` -> `arduboy.buttonsState()` 或标准按键 API

### 步骤 3：音频降级处理

若依赖 `ArduboyPlaytune` / `ArduboyTones` 且无法直接适配，先做条件编译或空实现，优先保证“可编译可运行”。

### 步骤 4：EEPROM 适配

如项目使用 EEPROM，需确保：

```cpp
#include <EEPROM.h>

void setup() {
  EEPROM.begin(1024);
}
```

写入后在 ESP8266 下调用：

```cpp
EEPROM.commit();
```

### 步骤 5：平台差异处理

常见 AVR 差异点：

- 硬件寄存器（`TCCR*`、`PORT*`）
- AVR 汇编
- 硬件定时器中断

建议用 `#ifndef ESP8266` 包裹 AVR 专用代码。

## 4. 兼容性分级

### 高兼容（优先移植）

- 只依赖 `Arduboy2` 常规绘图与按键
- 无复杂音频与寄存器操作

### 中兼容（可改造）

- 有基础音频依赖
- 少量平台相关代码

### 低兼容（工作量大）

- 深度依赖 AVR 寄存器或定时器
- 依赖 USB 通信链路

## 5. 常见报错速查

| 报错 | 常见原因 | 建议处理 |
|---|---|---|
| `ArduboyTones.h: No such file` | 音频库不可用 | 条件编译或先禁音 |
| `redefined PIN_*` | 平台分支冲突 | 检查 `Arduboy2Core.h` 条件编译 |
| `RX was not declared` | B 键定义冲突 | 使用 GPIO 数字常量（如 `3`） |
| `TCCR1A was not declared` | AVR 寄存器代码 | 包裹/移除 AVR 专用段 |
| 运行后黑屏 | I2C / 启动模式问题 | 检查 D1/D2 与 GPIO0 按键状态 |

## 6. 提交前最小验收清单

- [ ] 能编译通过
- [ ] 能进入主界面
- [ ] 上下左右 A/B 按键可用
- [ ] OLED 正常显示
- [ ] 使用 EEPROM 时读写正常
- [ ] 已添加 `README.md` 与 `manifest.json`

## 7. 推荐提交内容

每个移植 PR 至少包含：

1. 源码改动
2. 游戏 README（操作说明、已知问题）
3. `manifest.json`
4. 与上游差异说明（可放在 README）

## 8. 参考项目与经验来源

以下项目对 ESP8266 版 Arduboy 生态有较早实践价值，建议阅读其 README：

- `cheungbx/esp8266_arduboy2`：https://github.com/cheungbx/esp8266_arduboy2

可重点参考的经验点：

- ESP8266 上按键引脚紧张导致的映射取舍。
- I2C OLED 带来的刷新性能限制与复杂游戏掉帧风险。
- 音频库与 AVR 相关中断逻辑在 ESP8266 上的兼容性问题。
- EEPROM 使用时 `begin/commit` 的必要性。
